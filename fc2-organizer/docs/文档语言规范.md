# 文档语言规范

```text
状态     ：ACTIVE / 强制执行
适用范围 ：fc2-organizer 内所有由本项目维护的 Markdown 文档
生效时间 ：P4-C6 关闭之后（Post-Closure Governance Head）起
```

## 1. 默认语言

本项目的系统语言、产品默认语言和项目文档默认语言均为**简体中文**。

任何 AI 或开发者都不得根据仓库中的历史英文文档推断：

- 系统语言是英文；
- 产品界面语言是英文；
- 开发输出语言是英文。

## 2. 适用的文档类型

凡是新增或维护的项目文档，正文都必须使用简体中文，包括但不限于：

- 开发规格书
- Contract / 合同
- Plan / 计划
- HANDOFF / 交接
- Review / 复查
- Acceptance / 验收
- 开发提示词
- 治理说明
- 状态说明
- README 类项目说明

## 3. 允许保留英文的内容

以下内容可以保留英文原文：

- Python / JavaScript / SQL 等代码；
- API、function、class、enum、field 名称；
- 文件名和目录名；
- Git branch、SHA；
- shell / PowerShell 命令；
- traceback、pytest、Git 的原始输出；
- HTTP / JSON / XML 等协议中的固定名称；
- 外部库、项目、品牌、网站的正式名称；
- 必须精确匹配的 error message 或字面量。

标题中可以保留 Contract、Review、HANDOFF、PASS、FAIL、BLOCKED 等治理术语，但解释这些术语的正文必须使用中文。

## 4. 维护现有英文文档

- 在现有英文文档中新增或重写内容时，新增部分的正文必须使用中文。
- 如果任务明确属于“文档中文化迁移”，应把该文档的英文说明正文完整翻译为中文。
- 不得以“历史文档是英文”为理由继续用英文编写新文档。

## 5. 翻译的不变量

翻译只能改变自然语言表达，不得改变以下任何内容：

- 合同语义
- requirement
- finding ID
- severity
- SHA
- 测试数字
- API 行为
- 状态
- frozen boundary

## 6. 历史英文文档的迁移

仓库中现有的英文文档（规格书、合同、handoff、review 等）将在独立的 DOCS-CN migration 任务中分批转换为中文，并须在 P4-C7 开始之前完成。

迁移完成之前，不得因为尚未翻译完成而继续新增英文文档。
